# Math Hub 공통 구조

모든 단원이 같은 방식으로 붙도록 정한 형식이다. 단원을 하나 추가하는 일은 **유형 템플릿 파일을 쓰고, 단원 지도에 한 줄을 넣는 것**으로 끝나야 한다. 화면, 키패드, 정답 판정, 진도·복습은 공통 엔진이 맡는다.

이 문서는 설계안이다. 아직 코드는 없다. 단원 목록은 [roadmap.md](roadmap.md)에 있다.

- 1장: 문제 유형 템플릿 형식
- 2장: 단원 지도 데이터 형식
- 3장: 진도·복습 데이터 형식
- 4장: 파일 배치와 테스트
- 5장: 정해야 할 것

## 1. 문제 유형 템플릿

### 1.1 용어

| 말 | 뜻 | 예 |
|---|---|---|
| 단원 | 학습 지도의 한 칸. 통과 기준이 걸리는 단위. | `A10` 분수의 덧셈과 뺄셈 |
| 유형 | 한 단원 안의 문제 종류. 템플릿 하나가 유형 하나다. 복습이 걸리는 단위. | `A10.add-unlike` 분모가 다른 분수의 덧셈 |
| 단계 | 한 유형 안의 난이도. 단계가 오르면 숫자 범위가 넓어지고 조건이 풀린다. | 1단계: 한쪽 분모로 통분 → 3단계: 합이 1을 넘음 |
| 문제 | 템플릿에 무작위 숫자를 넣어 만든 한 문제. 저장하지 않고 그때그때 만든다. | 1/4 + 3/8 |

### 1.2 템플릿의 칸

| 칸 | 필수 | 내용 |
|---|---|---|
| `id` | ○ | `단원ID.유형이름`. 한 번 정하면 바꾸지 않는다(학습 기록의 열쇠). |
| `unit` | ○ | 속한 단원 ID. |
| `version` | ○ | 생성 규칙을 바꾸면 1 올린다(저장해 둔 진행 중 문제를 버릴지 판단하는 데 쓴다). |
| `title` | ○ | 유형 이름. 복습 목록과 피드백에 보인다. |
| `answer` | ○ | 답의 형식과 판정 규칙(1.4절). 키패드 모양도 여기서 정해진다. |
| `levels` | ○ | 단계 목록. 단계마다 **무작위 숫자 범위**(`vars`)와 **조건**(`where`)을 적는다. |
| `contexts` | | 문장제에 쓰는 상황 목록(사과 나누기, 리본 자르기 …). 같은 숫자 구조에 다른 상황을 입힌다. |
| `prompt(v, ctx)` | ○ | 문제 글. `$…$` 안은 KaTeX로 그린다. |
| `solve(v)` | ○ | **정답 계산**. 정확한 값(정수, 분수 …)을 돌려준다. |
| `verify(v, ans)` | ○ | 검산. `solve`와 **다른 방법**으로 답이 맞는지 확인한다(역연산, 대입 등). 테스트에서만 쓴다. |
| `hints(v)` | ○ | **힌트** 목록. 뒤로 갈수록 구체적이고, 마지막 힌트도 답은 말하지 않는다. |
| `steps(v)` | ○ | **단계별 풀이**. 마지막 줄의 값은 `solve`와 같아야 한다. |
| `mistakes` | ○ | **흔한 실수** 목록. 실수마다 "그 실수를 하면 나오는 오답"과 설명을 적는다(1.5절). |

### 1.3 예시: 분모가 다른 분수의 덧셈

```js
MH.defineType({
  id: 'A10.add-unlike',
  unit: 'A10',
  version: 1,
  title: '분모가 다른 분수의 덧셈',

  // 답은 분수. 약분하지 않아도 정답이지만 알려 준다. 대분수·소수로 써도 값이 같으면 정답.
  answer: { kind: 'fraction', reduce: 'notice' },

  // a/b + c/d. 위에서부터 차례로 뽑고, 함수로 적은 칸은 앞에서 뽑은 값을 쓸 수 있다.
  levels: [
    { name: '한쪽 분모로 통분',                        // 예: 1/4 + 3/8
      vars: { b: int(2, 6), k: int(2, 3), d: v => v.b * v.k,
              a: v => int(1, v.b - 1), c: v => int(1, v.d - 1) },
      where: v => coprime(v.a, v.b) && coprime(v.c, v.d) && sum(v).lt(1) },
    { name: '두 분모를 모두 바꿔 통분',                 // 예: 2/3 + 1/4
      vars: { b: int(2, 9), d: int(2, 9), a: v => int(1, v.b - 1), c: v => int(1, v.d - 1) },
      where: v => v.b % v.d !== 0 && v.d % v.b !== 0 && lcm(v.b, v.d) <= 36
               && coprime(v.a, v.b) && coprime(v.c, v.d) && sum(v).lt(1) },
    { name: '합이 1을 넘는 경우 포함',                  // 조건을 푼다: 합 < 1 제한 없음, 분모 12까지
      vars: { b: int(2, 12), d: int(2, 12), a: v => int(1, v.b - 1), c: v => int(1, v.d - 1) },
      where: v => v.b !== v.d && lcm(v.b, v.d) <= 60 && coprime(v.a, v.b) && coprime(v.c, v.d) },
  ],

  prompt: v => `$\\dfrac{${v.a}}{${v.b}} + \\dfrac{${v.c}}{${v.d}}$ 을 계산하세요.`,

  solve: v => F(v.a, v.b).add(F(v.c, v.d)),
  verify: (v, ans) => ans.sub(F(v.c, v.d)).equals(F(v.a, v.b)),      // 답에서 뒤 분수를 빼면 앞 분수

  hints: v => {
    const L = lcm(v.b, v.d);
    return [
      '분모가 다르면 바로 더할 수 없어요. 먼저 분모를 같게 만들어요(통분).',
      `${v.b}와 ${v.d}의 최소공배수는 ${L}이에요. 두 분수의 분모를 ${L}으로 바꿔 보세요.`,
      `$\\dfrac{${v.a}}{${v.b}} = \\dfrac{${v.a * L / v.b}}{${L}}$ 이에요. 다른 분수도 같은 방법으로 바꾼 뒤 분자끼리 더해요.`,
    ];
  },

  steps: v => { /* ① 통분 ② 분자끼리 더하기 ③ 약분 — { say, tex } 의 목록을 돌려준다 */ },

  mistakes: [
    { id: 'add-across',                                 // 1/4 + 3/8 = 4/12 로 계산
      wrong: v => F(v.a + v.c, v.b + v.d),
      explain: v => `분자는 분자끼리, 분모는 분모끼리 더했어요. 분모는 더하는 것이 아니라 같게 맞추는 수예요.` },
    { id: 'numerator-not-scaled',                       // 분모만 바꾸고 분자는 그대로 더함
      wrong: v => F(v.a + v.c, lcm(v.b, v.d)),
      explain: v => `분모를 ${lcm(v.b, v.d)}으로 바꿀 때 분자에도 같은 수를 곱해야 해요.` },
  ],
});

function sum(v) { return F(v.a, v.b).add(F(v.c, v.d)); }
```

`int`, `pick`, `F`, `lcm`, `coprime` 은 엔진이 주는 도구다. 템플릿 안에서는 `Math.random` 과 소수점 계산(`0.1 + 0.2` 같은 것)을 쓰지 않는다.

### 1.4 무작위 숫자와 조건

- **범위**(`vars`): `int(2, 9)`(정수 범위), `pick([2, 5, 10])`(목록에서 고르기), `sign()`(부호) 같은 추출기를 쓴다. 적은 순서대로 뽑는다.
- **조건**(`where`): 뽑은 숫자가 조건에 안 맞으면 다시 뽑는다. 200번 안에 못 찾으면 오류로 처리한다. 테스트가 이 경우를 잡아낸다(조건이 너무 빡빡하다는 뜻).
- **깔끔한 답**: "나누어떨어진다", "분모가 36 이하", "유한소수다" 같은 조건을 낮은 단계의 `where` 에 적고, 단계가 오르면 뺀다. 답을 먼저 정하고 문제를 거꾸로 만드는 방식(답 7, 나누는 수 6 → 42 ÷ 6)도 `vars` 의 함수 칸으로 쓸 수 있다.
- **난수**: 씨앗(seed)이 있는 난수를 쓴다. `(유형 id, version, 단계, seed)` 가 같으면 항상 같은 문제가 나온다. 그래서 문제 자체를 저장하지 않고 씨앗만 저장하면 풀던 문제를 다시 띄울 수 있고, 테스트에서 실패한 문제를 그대로 재현할 수 있다.
- **상황**(`contexts`): 문장제는 상황 목록에서 하나를 뽑아 `prompt` 에 넘긴다. 한국어 조사(은/는, 을/를, 으로/로)는 엔진의 `josa()` 도구가 숫자·낱말의 받침을 보고 붙인다.

### 1.5 답의 형식과 정답 판정

`answer.kind` 가 입력 방식, 읽는 법, 비교하는 법을 한꺼번에 정한다. 새 형식은 그 형식이 처음 필요한 단원에서 추가한다.

| kind | 입력 | 같은 값으로 인정 | 쓰기 시작하는 구간 |
|---|---|---|---|
| `int` | 숫자 키패드 | — | A |
| `quotient-remainder` | 몫 칸 + 나머지 칸 | — | A |
| `fraction` | 분자 칸 / 분모 칸 (+ 대분수의 자연수 칸) | 약분 전 분수, 대분수 ↔ 가분수, 소수 | A |
| `decimal` | 숫자 키패드 + 소수점 | 값이 같은 분수, 끝자리 0 (0.50) | A |
| `rational` | 위와 같고 부호 키 추가 | 위와 같음 | B |
| `expr` | 문자 키패드 (x, 지수, 괄호) | 전개했을 때 같은 다항식 | B |
| `surd` | 근호 키 | 값이 같은 표현(√8 = 2√2, 유리화 전) | B |
| `set` | 답 여러 개 (x = 2 또는 x = −3) | 순서 무관 | B |
| `inequality`, `pair`, `complex` … | 그때 정한다 | | B~C |
| `choice` | 보기 고르기 | — | 그래프·개념 문제 |

판정 결과는 네 가지다.

| 결과 | 뜻 | 통과 기준에서 |
|---|---|---|
| `correct` | 값도 형태도 맞음 | 정답 |
| `correct-note` | 값은 맞지만 형태를 더 다듬을 수 있음. "맞았어요. 약분하면 1/2이에요." | 정답 |
| `wrong` | 값이 다름 | 오답 |
| `invalid` | 답으로 읽을 수 없음(분모 0, 빈칸). 다시 입력하게 하고 기록하지 않는다. | 세지 않음 |

판정 순서:

1. 입력을 정확한 값으로 읽는다. 소수 `0.5` 는 분수 5/10으로 읽으므로 부동소수점이 끼어들지 않는다.
2. 정답과 값이 같으면 정답이다. 형태를 확인해서 `correct` 인지 `correct-note` 인지 정한다.
   - `reduce: 'notice'`(기본): 약분이 덜 됐으면 알려 주기만 한다.
   - `reduce: 'require'`: 약분 자체를 묻는 유형(A09)에서 쓴다. 덜 약분한 답은 "값은 같지만 더 약분할 수 있어요"라고 알리고 다시 입력하게 한다.
3. 값이 다르면 흔한 실수를 찾는다.
   - 먼저 그 유형의 `mistakes` 를 차례로 본다. 학생의 답이 `wrong(v)` 와 같으면 그 실수의 `explain` 을 보여 준다.
   - 없으면 엔진의 공통 실수를 본다: 부호가 반대, 역수, 10배·1/10배(소수점 위치), 1 차이(받아올림·받아내림), 분자와 분모가 뒤바뀜.
   - 그래도 없으면 "어디서 달라졌는지 풀이와 비교해 보세요"와 함께 단계별 풀이를 연다.
4. 찾은 실수의 `id` 를 기록한다(3장). 같은 실수가 반복되면 복습 때 그 설명을 먼저 보여 줄 수 있다.

실수의 오답이 우연히 정답과 같아지는 숫자 조합도 있다(예: 어떤 수에서는 잘못 계산해도 답이 같음). 그런 문제에서는 그 실수를 건너뛴다. 값이 아니라 쓴 모양을 봐야 하는 실수는 `wrong` 대신 `match(v, 입력)` 을 적는다.

### 1.6 문제를 푸는 화면의 흐름

1. 문제를 보여 준다. 시간 제한은 없다(설정에서 켤 수 있지만 기본은 꺼짐).
2. `힌트` 를 누르면 힌트가 하나씩 열린다.
3. 답을 내면 판정한다.
   - 정답: 짧게 확인하고 다음 문제로. `correct-note` 면 한 줄을 덧붙인다.
   - 오답: 실수 설명을 보여 주고 **한 번 더** 풀 기회를 준다. 기록은 첫 답으로 한다.
   - 두 번째도 틀리면 단계별 풀이와 정답을 보여 준다.
4. `풀이 보기` 는 언제든 누를 수 있다. 답을 내기 전에 풀이를 보면 그 문제는 오답으로 기록한다.

## 2. 단원 지도 데이터

`docs/shared/map.js` 하나에 구간과 단원을 모두 적는다. 허브 화면과 모든 영역 앱이 이 파일을 읽는다.

```js
MH.MAP = {
  stages: [
    // key 는 폴더 이름이자 허브 요약(MH.summary)의 이름이다.
    { id: 'A', key: 'basic',    name: '기초 계산',   level: '초등' },
    { id: 'B', key: 'middle',   name: '중학 수학',   level: '중학' },
    { id: 'C', key: 'common',   name: '공통수학',    level: '고1' },
    { id: 'D', key: 'algebra',  name: '대수',        level: '수능' },
    { id: 'E', key: 'calculus', name: '미적분Ⅰ',     level: '수능' },
    { id: 'F', key: 'stats',    name: '확률과 통계', level: '수능' },
  ],
  units: [
    { id: 'A09', title: '약분과 통분',
      summary: '크기가 같은 분수, 기약분수, 통분, 크기 비교',
      requires: ['A07', 'A08'],          // 선수 단원
      types: ['A09.reduce', 'A09.common-denominator', 'A09.compare'],   // 이 단원의 유형(나오는 순서)
      ready: true },                     // 만들어진 단원만 true
    { id: 'A10', title: '분수의 덧셈과 뺄셈',
      summary: '분모가 같은 경우 → 다른 경우 → 대분수',
      requires: ['A09'],
      types: [],                         // 아직 안 만든 단원은 비워 둔다
      ready: false },
    { id: 'C11', title: '행렬', summary: '…', requires: ['B04', 'B12'], types: [], ready: false,
      optional: true },                  // 건너뛰어도 되는 단원
  ],
};
```

규칙:

- 구간은 단원 ID의 첫 글자로 정해진다. 권장 순서는 `units` 배열의 순서다.
- `requires` 에는 바로 앞 단계만 적는다. 앞에 나온 단원만 가리킬 수 있다(순환 금지 — 테스트로 확인).
- 단원 ID와 유형 ID는 바꾸지 않는다. 단원을 사이에 끼워 넣어야 하면 `A09b` 처럼 새 ID를 만든다.
- 단원의 상태(잠김, 열림, 통과)는 지도에 적지 않는다. 지도와 진도 기록(3장)을 합쳐서 계산한다.

| 상태 | 조건 |
|---|---|
| 준비 중 | `ready: false` |
| 잠김 | 선수 단원 중 통과하지 않은 것이 있음 |
| 열림 | 선수 단원을 모두 통과 |
| 통과 | 통과 기준을 채움(3.2절) |

## 3. 진도·복습 데이터

### 3.1 저장 형식

localStorage의 `mathhub.progress` 한 곳에 모든 구간의 기록을 함께 둔다. 위 구간에서 아래 구간 문제를 섞어 내려면 기록이 한곳에 있어야 하기 때문이다. 문제 자체는 저장하지 않는다.

```js
{
  v: 1,                                  // 형식 버전. 형식을 바꾸면 올리고, 옛 기록을 새 형식으로 옮긴다.

  units: {
    'A10': {
      recent: '1101111111',              // 최근 10문제의 정오(1 정답, 0 오답). 오른쪽이 가장 최근.
      passed: 20772,                     // 통과한 날(날짜 번호). 아직이면 0.
      n: 37                              // 이 단원에서 푼 문제 수
    }
  },

  types: {
    'A10.add-unlike': {
      level: 1,                          // 지금 단계(0부터)
      run: 2,                            // 지금 단계에서 연속 정답 수
      n: 14, ok: 11,                     // 푼 수, 맞힌 수
      last: 20772,                       // 마지막으로 푼 날
      mistakes: { 'add-across': 2 }      // 실수 유형별 횟수
    }
  },

  reviews: [                             // 복습 예약. 유형마다 최대 한 줄.
    { type: 'A10.add-unlike',
      from: 20770,                       // 틀린 날
      step: 1,                           // 0 → 1일 뒤, 1 → 3일 뒤, 2 → 7일 뒤
      due: 20773,                        // 복습할 날 (= from + [1, 3, 7][step])
      mistake: 'add-across' }            // 그때 한 실수(없으면 null)
  ],

  days: { '20772': { n: 18, ok: 15 } },  // 날짜별 푼 수·맞힌 수 (연속 일수, 오늘 푼 수)

  current: { unit: 'A10', type: 'A10.add-unlike', version: 1, level: 1, seed: 918273, hints: 1 },
                                         // 풀던 문제. 앱을 닫았다 열어도 같은 문제가 뜬다.

  settings: { goal: 15, timer: false }   // 하루 목표 문제 수, 시간 제한(기본 꺼짐)
}
```

날짜 번호는 허브의 `MH.dnum()` 과 같다(그 지역 날짜 기준, 하루에 1씩 커짐). 허브 화면이 읽는 요약(`MH.summary`)은 이 기록에서 계산해서 써 준다.

### 3.2 단원 통과

- 기준: 그 단원 **최근 10문제 중 9문제 이상 정답**이면 통과.
- `recent` 에 들어가는 것은 그 단원을 공부하면서 푼 그 단원 문제뿐이다. 복습 문제와 섞어 낸 아래 단원 문제는 들어가지 않는다.
- 답을 내기 전에 풀이를 본 문제는 오답이다. 힌트만 본 문제는 정답으로 친다.
- 제안(5장에서 결정): 쉬운 단계만 풀고 통과하는 일을 막기 위해, **모든 유형이 마지막 단계에 올라온 뒤의 문제만** `recent` 에 넣는다. 그 전까지는 "연습 중"으로 보여 준다.
- 단계는 같은 유형을 연속 2번 맞히면 한 칸 오르고, 틀리면 한 칸 내려간다.
- 통과는 되돌리지 않는다. 통과한 단원을 나중에 틀려도 복습 예약만 걸린다.

### 3.3 바로 통과 시험

이미 아는 단원을 빨리 넘기기 위한 길이다. 열린 단원에서 `바로 통과 시험` 을 고르면 모든 유형의 마지막 단계 문제를 섞어 10문제 낸다. 9문제 이상 맞히면 통과다. 떨어지면 틀린 유형부터 평소대로 공부한다.

### 3.4 복습 (1일 · 3일 · 7일)

- 문제를 틀리면 그 **유형**을 복습에 넣는다: `from` = 오늘, `step` = 0, `due` = 내일.
- 복습 날이 되면 같은 유형의 **새 숫자** 문제를 낸다(틀렸던 그 단계로).
- 맞히면 `step` 을 올리고 `due` 를 `from + 3`, 다음엔 `from + 7` 로 옮긴다. 늦게 풀었으면 적어도 내일로 잡는다. 세 번(1일·3일·7일)을 다 맞히면 목록에서 뺀다.
- 복습에서 틀리면 처음으로 돌아간다: `from` = 오늘, `step` = 0.
- 이미 복습 목록에 있는 유형을 평소 공부에서 또 틀려도 마찬가지로 처음으로 돌린다.

### 3.5 아래 단원 섞기

- 지금 단원을 공부하는 동안 문제의 약 20%(5문제에 1문제)는 이미 통과한 단원에서 낸다.
- 고르는 우선순위: ① 지금 단원의 선수 단원 ② 푼 지 오래된 유형(`last`) ③ 정답률이 낮은 유형(`ok / n`).
- 섞어 낸 문제는 "지난 단원" 표시를 붙인다. 지금 단원의 통과 기준에는 넣지 않고, 틀리면 복습에 넣는다.

### 3.6 하루 학습의 순서

1. 오늘 날짜가 된 복습 문제 (많이 밀렸으면 하루 10문제까지만, 오래된 것부터)
2. 지금 단원의 새 문제 + 섞어 낸 아래 단원 문제
3. 하루 목표(기본 15문제)를 채우면 "오늘은 여기까지"를 보여 준다. 더 풀 수도 있다.

### 모든 유형에 자동으로 거는 검사

유형을 등록하기만 하면 아래 검사가 걸린다. 단계마다 문제 1,000개를 만들어 확인한다.

| 검사 | 내용 |
|---|---|
| 생성 | 1,000개가 모두 만들어진다(다시 뽑기 한도를 넘지 않는다). |
| 조건 | 모든 문제가 그 단계의 `where` 와 답 형식의 조건(분모 범위, 유한소수 등)을 지킨다. |
| 정답 | `verify(v, solve(v))` 가 모두 참이다. |
| 판정 | 정답을 입력하면 `correct`. 약분 전 형태·대분수·소수로 입력하면 `correct` 또는 `correct-note`. |
| 실수 | 각 실수의 오답을 입력하면 `wrong` 이고 그 실수의 설명이 나온다. |
| 풀이 | 풀이의 마지막 값이 정답과 같다. 힌트가 1개 이상이고 정답을 그대로 담고 있지 않다. |
| 재현 | 같은 씨앗이면 같은 문제가 나온다. |
| 다양성 | 1,000개 중 서로 다른 문제가 충분히 많다(범위가 좁은 유형은 가능한 문제를 모두 낸다). |

지도 검사: 선수 단원이 실제로 있고 앞에 나오는지, 순환이 없는지, 지도의 유형 ID와 등록된 유형이 서로 맞는지.

## 5. 정해야 할 것

제안을 적어 두었다. 다르게 하고 싶은 것만 알려 주면 된다.

| 질문 | 제안 |
|---|---|
| 잠긴 단원을 아예 못 열게 할까? | 선수 단원을 통과해야 열린다. 대신 열린 단원은 `바로 통과 시험`으로 빨리 넘길 수 있다. |
| 쉬운 단계 문제도 통과 기준에 넣을까? | 넣지 않는다. 모든 유형이 마지막 단계에 올라온 뒤의 문제만 센다(3.2절). |
| 힌트를 본 문제는 정답인가? | 정답. 풀이를 먼저 본 문제만 오답. |
| 하루 목표 | 15문제. 설정에서 10~30 사이로 바꿀 수 있게. |
| 섞어 내는 비율 | 20%. |
| 기기를 바꾸면 기록이 사라진다 | 기록을 파일로 내보내고 가져오는 기능을 나중에 만든다. |
| 계획 문서의 위치 | 지금은 요청대로 `docs/` 에 두었다. `docs/` 는 사이트 폴더라서 이 두 문서도 사이트 주소로 열린다(5장 아래 메모). |

메모: `tools/build_sw.py` 는 `docs/` 안의 모든 파일을 오프라인 저장 목록에 넣는다. 다음에 코드를 만질 때 `.md` 파일은 목록에서 빼도록 고친다.
